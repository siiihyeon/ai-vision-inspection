Vision 순수 통합시험은 다음을 포함합니다.

- RGB8 PNG/manifest 원자 저장과 SHA/readback
- restart capture identity 탐색
- skew 초과 시 같은 capture ID로 A station 전체 카메라 재촬영
- 실패 attempt 보존
- enqueue commit된 journal job만 재시작 복원
- enqueue 완료 job을 재촬영하지 않고 새 runtime worker가 처리
- ProductResultLocked journal terminal 상태
- ENQUEUE_BLOCKED 대기시간을 제외하고 실제 enqueue 순간부터 timeout clock 시작
- sim capture→path Queue→2 workers→공유 model 결과
- OpenCV decode BGR→model input RGB 변환 계약
- NaN model score 거부
- MVS uint32 counter wrap/frame correlation 순수 함수
- MVS SDK raw version 불일치 시 hardware 초기화 차단

## WSL2 설치 시도

`wsl.exe --install --no-distribution`을 관리자 권한 경로로 실행했습니다.

- 실행시간: 약 3.9초(8분 제한 이내)
- exit code: 0
- 결과: WSL/Virtual Machine Platform 구성요소 설치 요청은 완료
- 현재 `wsl --status`: 기본 버전은 2지만 WSL2를 아직 사용할 수 없다고 보고하며,
  Virtual Machine Platform 활성화와 firmware virtualization 확인을 안내
- DISM 기능 상태 재확인: 현재 Codex 프로세스에는 DISM이 요구하는 완전한 관리자
  token이 없어 error 740으로 읽기조차 거부됨

먼저 Windows를 재부팅해야 설치 요청의 적용 여부를 판단할 수 있습니다. 재부팅 후에도
같은 안내가 남으면 BIOS/UEFI의 Intel VT-x/AMD-V와 Windows 기능 상태를 사용자가
관리자 PowerShell에서 확인해야 합니다. 재부팅은 열려 있는 사용자 작업을 종료하므로
Codex가 자동 수행하지 않았습니다.

## 재부팅 후 이어서 실행할 순서

관리자 PowerShell:

```powershell
wsl --status
wsl --install -d Ubuntu-24.04
wsl --list --verbose
```

Ubuntu 24.04 첫 실행에서 사용자 생성 후, Microsoft의 ROS 2 Jazzy 공식 설치 절차로
repository/key/package를 설치합니다. 각 설치 단계는 사용자 정책대로 8분을 넘기면
중단하고 이 문서를 갱신합니다.

설치 완료 후 Ubuntu shell:

```bash
python3 --version
source /opt/ros/jazzy/setup.bash
cd "/mnt/c/Users/SNU_ANCHOR_P3/Desktop/Vision Inspection/github-sync-ai-vision-inspection/ros2_ws"
python3 -m pyflakes src tools
python3 tools/verify_skeleton.py
python3 tools/test_domain_contracts.py
python3 tools/test_vision_node.py
colcon build --symlink-install
source install/setup.bash
colcon test --event-handlers console_direct+
colcon test-result --verbose
```

WSL2는 build/sim 검사 환경입니다. 실제 공정 PC의 GigE NIC timing, MVS, GPU 및 장시간
운전 합격은 native Ubuntu 24.04에서 [MVS_실장비_검증절차.md](MVS_실장비_검증절차.md)를
따라 별도로 수행합니다.
