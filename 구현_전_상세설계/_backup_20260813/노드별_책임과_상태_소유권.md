# 비전검수 시스템 노드별 책임과 상태 소유권

## 1. 문서 목적

본 문서는 비전검수 시스템을 구성하는 4개 노드의 책임과 상태 소유권을 정의한다.

대상 노드는 다음과 같다.

- `MasterNode`
- `ControlNode`
- `VisionNode`
- `LogNode`

이 문서에서는 각 노드가 어떤 상태와 데이터의 원본을 가지는지 정한다. 구체적인 상태 전이 조건, 통신 메시지 구조, 타임아웃 값과 구현 코드는 후속 설계에서 정의한다.

---

## 2. 상태 소유권 원칙

### 2.1 단일 소유자 원칙

하나의 상태에는 최종 값을 결정하고 변경할 수 있는 소유 노드가 하나만 존재해야 한다.

다른 노드는 상태를 전달받아 조회하거나 임시로 복사할 수 있지만, 원본 상태를 독립적으로 변경하지 않는다.

### 2.2 요청 상태와 실제 상태의 분리

장비 동작은 마스터가 요청하고 컨트롤 노드가 실제 수행 결과를 확정한다.

```text
MasterNode
upper_requested_state = RUN_CONV

ControlNode
upper_actual_state = POSITIONING
```

- 요청 상태의 소유자: `MasterNode`
- 실제 장비 상태의 소유자: `ControlNode`

### 2.3 제품 ID와 FIFO의 단일 원본

제품 ID와 단일 FIFO는 `MasterNode`만 소유한다.

`ControlNode`와 `VisionNode`는 `MasterNode`가 전달한 제품 ID를 사용하며, 별도의 제품 ID 또는 물리 순서 FIFO를 생성하지 않는다.

### 2.4 지역 오류와 전체 오류의 분리

각 노드는 자신이 직접 확인할 수 있는 지역 오류를 감지하고 오류 정보를 `MasterNode`에 전달한다.

전체 시스템의 `FAULT_STOP` 여부는 원칙적으로 `MasterNode`가 결정한다. 단, 통신 단절이나 안전장치 작동처럼 즉시 정지가 필요한 경우 `ControlNode`는 마스터 응답을 기다리지 않고 물리 장비를 안전 정지할 수 있다.

---

## 3. 전체 노드 구성

```text
ControlNode ⇄ MasterNode ⇄ VisionNode
     └──────────┬──────────┘
              LogNode
```

| 노드 | 핵심 역할 | 주된 상태 원본 |
|---|---|---|
| `MasterNode` | 전체 공정 조율과 제품 추적 | 시스템 상태, 제품 상태, FIFO, 최종 판정 |
| `ControlNode` | 물리 장비 입출력과 구동 | 센서, 컨베이어, 모터 위치, 액추에이터 실제 상태 |
| `VisionNode` | 이미지 취득과 비동기 추론 | 카메라, 촬영 작업, 추론 작업, 비전 결과 |
| `LogNode` | 이벤트 및 결과 영구 저장 | 저장 상태, 로그 레코드 |

---

## 4. MasterNode

### 4.1 한 줄 책임

제품의 물리적 진행 순서와 전체 검사 공정을 조율하고 시스템의 최종 운전 판단을 내린다.

### 4.2 소유하는 상태

- 전체 시스템 운전 상태
  - `BOOT`
  - `INITIALIZING`
  - `READY`
  - `RUN_SYS`
  - `PAUSING`
  - `PAUSED`
  - `FAULT_STOP`
  - `RESETTING`
- 운전 상태머신과 분리된 프로그램 종료 절차 상태
  - `IDLE`
  - `SHUTTING_DOWN`
  - `SHUTDOWN_COMPLETE`
- 제품별 물리 진행 상태
  - `STATION_A_WAIT`
  - `STATION_A_DONE`
  - `FLIPPING`
  - `STATION_B_WAIT`
  - `STATION_B_DONE`
  - `SENSOR3_WAIT`
  - `AT_SENSOR3`
  - `ACTUATING`
  - `DONE`
- 제품별 스테이션 검사 반영 상태
- 제품별 최종 판정 상태
  - `PENDING`
  - `OK`
  - `NG`
  - `FORCED_NG`
- 비동기 검사 결과 반영 상태
  - `WAITING`
  - `APPLIED`
  - `LATE_IGNORED`
  - `LATE_CONFLICT_IGNORED`
- 상층·하층 컨베이어 요청 상태
- 제품별 액추에이터 처리 요청 상태
- 전체 시스템 오류 정지 상태와 오류 사유

> 제품 이동과 비전 추론은 동시에 진행될 수 있으므로 물리 진행 상태와 추론 작업 상태를 하나의 선형 상태로 합치지 않는다.

### 4.3 소유하는 데이터

- 제품 ID 발급 순번
- 활성 제품 단일 FIFO
- 제품별 센서 1·2·3 반영 시각
- 제품별 현재 물리 구간
- 제품별 스테이션 A/B 촬영 결과 반영값
- 제품별 스테이션 A/B 검사 결과 반영값
- 제품별 최종 판정과 강제 NG 사유
- 액추에이터에 전달할 제품별 통과·배출 결정
- 마지막으로 정상 반영한 이벤트 ID
- 센서별 정상 수락 이벤트 누적 횟수
- 현재 `FAULT_STOP` 코드와 상세 원인

### 4.4 입력

#### ControlNode에서 수신

- 센서 1·2·3 감지 이벤트
- 센서별 이벤트 순번과 감지 시각
- 컨베이어 실제 상태
- 촬영 위치 도달 및 정지 완료
- 컨베이어 재가동 완료
- 액추에이터 동작 완료 또는 실패
- 센서·모터·액추에이터 오류
- `ControlNode` 생존 신호

#### VisionNode에서 수신

- 촬영 성공 또는 실패
- 촬영된 카메라 목록
- 카메라별 촬영 오류 정보
- 스테이션별 추론 결과
- 카메라별 점수와 처리시간
- 늦게 도착한 추론 결과
- 카메라 또는 비전 작업 오류
- `VisionNode` 생존 신호

#### LogNode에서 수신

- 로그 저장 성공 또는 실패
- 저장장치 용량 및 로그 노드 상태

### 4.5 출력

#### ControlNode로 전송

- 상층·하층 컨베이어 시작·정지 명령
- 촬영 위치까지의 이동 명령
- 촬영을 위한 일시 정지 명령
- 촬영 완료 후 재가동 명령
- 액추에이터 정상 통과 또는 불량 배출 명령
- 전체 안전 정지 명령
- 수동 리셋 이후 초기화 명령

#### VisionNode로 전송

- 제품 ID와 스테이션 ID가 포함된 촬영 요청
- 비전 작업 취소 또는 초기화 요청
- 시스템 리셋 이후 비전 상태 재확인 요청

#### LogNode로 전송

- 제품 생성·갱신·완료 이벤트
- 시스템 상태 변경 이벤트
- 최종 판정과 강제 NG 사유
- `FAULT_STOP` 코드와 발생 당시 상태

### 4.6 하지 않는 일

- 센서 전기 신호 직접 판독
- 모터 드라이버와 액추에이터 직접 구동
- 실제 모터 위치를 독립적으로 확정
- 카메라 SDK 직접 호출
- 이미지 전처리와 PatchCore 추론 수행
- 로그 파일 직접 기록

카메라 촬영 시 `VisionNode`는 카메라 설정·ARM·프레임 수집을 담당하고, `ControlNode/Mega`는 조명 안정화와 실제 하드웨어 트리거 펄스를 담당한다.

### 4.7 장애 발생 시 영향

`MasterNode`와 통신할 수 없으면 제품 ID, FIFO와 전체 공정 판단을 신뢰할 수 없다.

```text
MasterNode 통신 두절
→ ControlNode가 컨베이어와 액추에이터 안전 정지
→ 자동 재가동 금지
→ 작업자 확인과 수동 복구
```

### 4.8 확정 운영 정책

#### 프로그램 종료

`SHUTDOWN`은 전체 시스템 운전 상태머신에 포함하지 않고 별도의 프로그램 종료 절차로 처리한다.

```text
종료 요청
→ 신규 제품과 촬영 요청 차단
→ 상층·하층 컨베이어 안전 정지
→ 진행 중인 데이터와 로그 저장 시도
→ 화면에 SHUTTING_DOWN 표시
→ 카메라·통신·장비 연결 종료
→ 화면에 SHUTDOWN_COMPLETE 표시
→ 프로그램 종료
```

#### 작업자 일시 정지

작업자가 `PAUSED`를 요청하면 상층·하층 컨베이어를 즉시 안전 정지한다.

- 활성 FIFO와 제품별 진행 상태를 유지한다.
- 컨베이어별 실제 스텝 위치를 유지한다.
- 이미 시작된 비전 추론은 완료할 수 있으며 결과는 제품 ID 기준으로 반영한다.
- 재개 요청 시 실제 컨베이어 위치, FIFO와 센서 상태의 일치 여부를 확인한 후 `RUN_SYS`로 복귀한다.

#### 로그 장애

일반적인 `LogNode` 장애는 `FAULT_STOP`으로 승격하지 않고 경고 상태로 처리한다. 중요 기록을 로컬 spool에 더 이상 보존하기 어려운 위험 한도에 도달하면 `PAUSING → PAUSED`로 전환하고 저장소 복구와 backlog 저장을 요구한다. 로그 장애만으로 `FAULT_STOP`하지 않는다.

## 5. ControlNode

### 5.1 한 줄 책임

센서, 상·하층 컨베이어와 액추에이터를 직접 제어하고 물리 장비의 실제 상태를 보고한다.

### 5.2 소유하는 상태

- 상층 컨베이어 실제 상태
- 하층 컨베이어 실제 상태
  - `DISABLED`
  - `STOP_CONV`
  - `RUN_CONV`
  - `POSITIONING`
  - `SETTLING`
  - `CAPTURE_HOLD`
  - `FAULT`
- 센서 1·2·3 실제 입력 상태
  - `CLEAR`
  - `BLOCKED`
  - `FAULT`
- 액추에이터 실제 동작 상태
  - `UNINITIALIZED`
  - `IDLE`
  - `WAITING_POSITION`
  - `ACTUATING`
  - `CONFIRMED`
  - `FAULT`
- 액추에이터 실제 분기 위치 상태
  - `PASS_POSITION`
  - `REJECT_POSITION`
  - `MOVING_TO_PASS`
  - `MOVING_TO_REJECT`
  - `FAULT`
- 물리 비상정지 입력·래치 상태
- 하드웨어 카메라 트리거와 타이밍 조명 출력 상태
- 모터 드라이버와 I/O 연결 상태
- `MasterNode` 통신 및 생존 신호 상태

### 5.3 소유하는 데이터

- 상층·하층 모터의 현재 스텝 위치
- 센서별 원신호와 디바운스 처리 결과
- 센서별 물리 감지 이벤트 순번
- 컨베이어별 현재 속도와 방향
- 진행 중인 모션 명령 ID
- 액추에이터 명령 ID와 완료 여부
- 액추에이터 제품별 예약 큐와 `completion_id`
- TB6600 스텝모터 드라이버의 PUL·DIR·ENA 출력 상태
- PoC 래칭형 물리 비상정지 상태
- 스테이션별 카메라 트리거·조명 채널 상태
- 장비 오류 코드

### 5.4 입력

#### MasterNode에서 수신

- 컨베이어 시작·정지 명령
- 촬영 위치 이동 명령
- 촬영 정지와 재가동 명령
- 액추에이터 통과·배출 명령
- 전체 안전 정지 명령
- 오류 초기화 및 재가동 명령
- `MasterNode` 생존 신호

### 5.5 출력

#### MasterNode로 전송

- 센서 감지 이벤트와 이벤트 순번
- 컨베이어 실제 상태 변경
- 목표 스텝 위치 도달
- 모터 정지 및 재가동 완료
- 액추에이터 동작 완료 또는 실패
- 센서·모터·액추에이터 오류
- `ControlNode` 생존 신호

#### LogNode로 전송

- 센서 원이벤트
- 모터 및 액추에이터 동작 이벤트
- 장비 오류와 안전 정지 정보

### 5.6 하지 않는 일

- 제품 ID 독립 생성
- 별도의 제품 FIFO 운영
- 센서 이벤트와 특정 제품을 독립적으로 연결
- 이미지 촬영과 추론 수행
- 제품 최종 OK·NG 판정
- 추론 미완료 제품의 강제 NG 여부 결정

### 5.7 장애 발생 시 영향

- 센서·모터·액추에이터 오류를 감지하면 오류 정보와 실제 장비 상태를 `MasterNode`에 전달한다.
- 통신 단절이나 안전장치 작동처럼 즉시 대응해야 하는 상황에서는 `MasterNode`의 추가 명령을 기다리지 않고 장비를 안전 정지한다.
- 안전 정지 이후 자동으로 운전을 재개하지 않는다.
- PoC 물리 비상정지는 래칭형 빨간 스위치가 TB6600 구동전원을 일괄 차단한다. PC와 Arduino Mega 전원은 유지하며 버튼 해제만으로 자동 재가동하지 않는다.

### 5.8 확정 및 미정 항목

확정 사항:

- 촬영 정지 상태명은 `CAPTURE_HOLD`로 사용한다.

실물 장비 확인 후 결정할 사항:

- 센서별 `BLOCKED` 디바운스 시간
- 센서별 `CLEAR` 유지시간과 1회 감지 잠금 해제 조건
- 컨베이어 촬영 위치 도달 판단 허용오차
- 액추에이터 구동기·위치 확인 신호와 전환 시간
- 물리 비상정지 스위치의 전압·전류 정격과 Mega 상태 입력 배선
- 카메라 하드웨어 트리거 전압·펄스폭과 조명 채널 배선

## 6. VisionNode

### 6.1 한 줄 책임

카메라 4대의 이미지 취득과 PatchCore 추론을 수행하고 제품 ID 기준의 검사 결과를 생성한다.

### 6.2 소유하는 상태

- 카메라별 연결 상태
  - `DISCONNECTED`
  - `IDLE`
  - `CAPTURING`
  - `FAULT`
- 스테이션별 촬영 작업 상태
  - `IDLE`
  - `REQUESTED`
  - `CAPTURING`
  - `IMAGE_READY`
  - `FAILED`
- 제품·스테이션별 추론 작업 상태
  - `QUEUED`
  - `RUNNING`
  - `DONE`
  - `FAILED`
- 내부 추론 작업 큐 상태
- 카메라별 하드웨어 트리거 준비 상태
- `MasterNode` 통신 및 생존 신호 상태

### 6.3 소유하는 데이터

- 카메라 ID와 스테이션 배정 정보
- 촬영 요청 ID와 제품 ID 연결 정보
- 촬영 이미지 및 저장 경로
- 촬영 시각과 카메라별 성공·실패 정보
- ROI 및 전처리 결과
- 카메라별 PatchCore 원점수와 정규화 점수
- 카메라별 OK·NG 결과
- 스테이션별 검사 결과
- 촬영·대기·추론 처리시간
- 카메라별 촬영 실패 누적·연속 횟수
- 제품×스테이션 촬영 작업 ID인 `CaptureID`
- 이미지 한 장마다 발급하는 `ImageID`

### 6.4 입력

#### MasterNode에서 수신

- 제품 ID와 스테이션 ID가 포함된 촬영 요청
- 촬영 작업 취소 또는 초기화 요청
- 오류 복구 이후 상태 재확인 요청
- `MasterNode` 생존 신호

### 6.5 출력

#### MasterNode로 전송

- 이미지 취득 성공 응답
- 이미지 취득 실패 응답과 실패 카메라 ID
- 카메라별 점수와 결과
- 스테이션별 검사 결과
- 촬영·추론 처리시간
- 늦게 도착한 추론 결과
- 카메라 연결 또는 비전 처리 오류
- `VisionNode` 생존 신호

#### LogNode로 전송

- 이미지 경로와 촬영 메타데이터
- 카메라별 원점수·정규화 점수
- 촬영·추론 오류 상세 정보
- 비전 처리시간과 작업 큐 상태

### 6.6 하지 않는 일

- 제품 ID 독립 생성
- 물리적 제품 FIFO 운영
- 컨베이어와 액추에이터 직접 제어
- 촬영 완료 후 컨베이어 재가동 직접 결정
- 전체 시스템 `FAULT_STOP` 상태 직접 변경
- 센서 3 도착 시 강제 NG 여부 직접 결정

### 6.7 장애 발생 시 영향

#### 촬영 실패 응답이 정상적으로 전달된 경우

```text
필수 이미지 취득 실패
→ MasterNode에 CAPTURE_FAILED 전달
→ 해당 제품 FORCED_NG
→ 컨베이어 재가동
→ 시스템 계속 운전
```

#### VisionNode 응답 또는 통신 자체가 끊어진 경우

촬영 종료 여부와 제품 연결을 확정할 수 없으므로 개별 제품 촬영 실패와 구분하여 시스템 통신 오류로 처리한다.

### 6.8 확정 및 미정 항목

#### 촬영 방식

동일 스테이션에 배정된 카메라는 공유 조명을 사용하여 동시에 촬영한다.

- 사선 카메라 3대가 배정된 스테이션은 3대를 동시 촬영한다.
- 수직 카메라 1대가 배정된 스테이션은 해당 카메라만 촬영한다.
- 스테이션 촬영 성공은 해당 스테이션의 필수 카메라 이미지가 모두 확보된 경우에만 인정한다.

#### 일부 카메라 촬영 실패

필수 카메라 중 하나라도 촬영에 실패하면 해당 스테이션 촬영 결과를 `FAILED`로 확정하고 제품을 `FORCED_NG` 처리한다.

- 실패 카메라 ID와 오류 원인을 기록한다.
- 정상적으로 확보된 이미지는 진단용으로 파일에 저장한다.
- 촬영에 실패한 스테이션은 정상 판정용 추론을 생략한다.
- 반대쪽 스테이션 검사는 정상 흐름대로 계속 수행한다.
- 제품은 FIFO 순서대로 센서 3까지 이동하여 불량 배출한다.
- 필수 카메라는 최대 1회 재촬영한다. 최초 촬영과 재촬영이 모두 실패한 경우 `FORCED_NG`로 확정한다.

장비 성능 측정 후 결정할 사항:

- 추론 작업 큐 최대 길이
- 반복 촬영 실패 경고 발생 횟수 또는 비율

## 7. LogNode

### 7.1 한 줄 책임

각 노드에서 발생한 제품·운전·오류 이벤트를 변경 없이 영구 저장하고 조회 가능한 형태로 관리한다.

### 7.2 소유하는 상태

`LogNode`는 별도의 다단계 운전 FSM을 두지 않는다. 다음 두 상태 원본만 관리한다.

- 로그 저장소·노드 `health_state`
- 로컬 보존 상태인 `SpoolState`

`DEGRADED`는 저장 기능 저하를 뜻하는 health 상태이며 시스템 운전 FSM의 원본이 아니다.

### 7.3 소유하는 데이터

- 제품별 전체 처리 이력
- 센서 이벤트 기록
- 컨베이어와 액추에이터 운전 기록
- 카메라 촬영 정보와 이미지 경로
- PatchCore 점수와 검사 결과
- 최종 판정과 강제 NG 사유
- 노드 간 명령·응답 이력
- `FAULT_STOP` 발생 원인과 직전 이벤트
- 노드별 처리시간과 통신 상태 기록

### 7.4 입력

#### 전체 노드에서 수신

- 제품·운전·오류 로그 이벤트
- 시스템 및 장비의 실시간 상태 이벤트
- 이벤트 발생 노드와 시각
- 제품 ID, 스테이션 ID, 카메라 ID
- 메시지 ID와 관련 명령 ID
- 상태 변경 전·후 값
- 오류 코드와 사람이 읽을 수 있는 상세 원인

#### CLI/HMI에서 수신

- 제품 ID, 기간, 판정 조건을 이용한 로그 조회 요청

운전 명령은 `CLI/HMI → MasterNode`로 직접 전달하며 LogNode가 중계하지 않는다.

### 7.5 출력

- 로그 저장 성공 또는 실패
- 로그 쓰기 큐 상태
- 저장장치 남은 용량
- 제품 ID 기준 조회 결과
- 오류 및 통계 조회 결과

### 7.6 하지 않는 일

- 제품 상태와 FIFO 직접 변경
- 컨베이어 또는 액추에이터 제어
- 이미지 촬영과 추론 수행
- 제품 최종 판정 변경
- `FAULT_STOP` 직접 결정
- 기록된 이벤트를 근거로 실제 운전 상태를 임의 변경

### 7.7 장애 발생 시 영향

로그 장애가 발생해도 `LogNode`가 실제 장비나 제품 상태를 직접 변경하지 않는다.

```text
로그 저장 실패 또는 저장장치 이상
→ LogNode health 상태를 DEGRADED로 변경
→ MasterNode와 HMI에 경고 전송
→ 중요 기록 보존 가능하면 검사 운전 계속
→ spool 위험 한도 도달 시 PAUSING→PAUSED
→ FAULT_STOP으로는 승격하지 않음
```

저장 기능이 복구되면 복구 시각과 누락 가능 구간을 새 로그에 기록한다.

### 7.8 저장 방식과 이미지 연결

#### 저장 형식

- 제품·촬영·추론·운전·오류 메타데이터: SQLite
- 촬영 이미지 원본: 일반 이미지 파일
- 외부 공유 및 분석용 결과: 필요 시 SQLite에서 CSV로 내보내기

SQLite는 최소한 다음 테이블로 구성한다.

```text
products
captures
inference_results
system_events
faults
sessions
```

#### 이미지와 제품 로그 연결

제품×스테이션 촬영 작업마다 고유한 `CaptureID`를 MasterNode가 발급한다. 동일 촬영 작업의 여러 카메라 이미지는 같은 `CaptureID`를 공유하고, 이미지 한 장마다 VisionNode가 별도의 `ImageID`를 발급한다.

```text
ProductID
CaptureID
ImageID
StationID
CameraID
CaptureTime
CaptureStatus
ImageRelativePath
ErrorCode
```

권장 이미지 경로 구조는 다음과 같다.

```text
images/
└─ YYYY-MM-DD/
   └─ ProductID/
      ├─ STATION_A/
      │  ├─ CAM_01_ImageID.png
      │  ├─ CAM_02_ImageID.png
      │  └─ CAM_03_ImageID.png
      └─ STATION_B/
         └─ CAM_04_ImageID.png
```

SQLite에는 절대 경로 대신 `images/` 루트를 기준으로 한 상대 경로를 저장한다. 촬영 실패로 이미지가 없으면 경로는 비워두고 `CaptureStatus=FAILED`와 오류 코드를 저장한다.

### 7.9 로그 보존 정책

- 제품 로그, 운전 로그, 오류 로그와 촬영 이미지를 자동 삭제하지 않고 모두 저장한다.
- 저장장치 용량이 부족해지면 HMI에 경고를 표시한다.
- 오래된 데이터의 백업·이동·삭제는 작업자가 수동으로 수행한다.
- 자동 삭제 기능은 별도 요구가 확정되기 전까지 구현하지 않는다.

저장장치 용량 경고 임계값과 백업 위치는 실제 저장장치 용량 확정 후 결정한다.

### 7.10 HMI와 로그 조회 기능

과거 로그 조회 기능은 `LogNode` 프로세스에 포함한다. 실제 HMI 구성은 운영 단계에서 확정한다.

- 과거 제품, 이미지, 점수와 오류 조회는 LogNode의 SQLite를 사용한다.
- 실시간 상태는 MasterNode·ControlNode·VisionNode의 상태 이벤트를 구독하여 표시한다.
- 개발 단계의 시작·일시 정지·재개·리셋 요청은 CLI가 MasterNode를 직접 호출한다. 향후 HMI도 동일하게 MasterNode를 직접 호출한다.
- HMI는 ControlNode에 모터 또는 액추에이터 명령을 직접 보내지 않는다.
- MasterNode가 현재 상태와 안전 조건을 확인한 뒤 ControlNode에 실제 명령을 전달한다.

## 8. 상태·데이터 소유권 표

| 상태 또는 데이터 | 원본 소유 노드 | 다른 노드의 사용 방식 | 비고 |
|---|---|---|---|
| 전체 시스템 운전 상태 | `MasterNode` | Control·Vision·Log에서 조회 | `RUN_SYS`, `PAUSED`, `FAULT_STOP` 등 |
| 제품 ID 발급 순번 | `MasterNode` | 다른 노드는 전달받아 사용 | 독립 생성 금지 |
| 단일 활성 FIFO | `MasterNode` | Control·Vision은 운영하지 않음 | 물리 순서의 논리적 원본 |
| 제품 물리 진행 상태 | `MasterNode` | Log에서 기록 | `FLIPPING` 포함 |
| 제품 최종 판정 | `MasterNode` | Control은 액추에이터 명령으로 수신 | `OK`, `NG`, `FORCED_NG` |
| 컨베이어 요청 상태 | `MasterNode` | Control이 명령으로 수신 | 목표 상태 |
| 컨베이어 실제 상태 | `ControlNode` | Master가 응답으로 수신 | `RUN_CONV` 등 |
| 모터 실제 스텝 위치 | `ControlNode` | Master가 위치 이벤트로 수신 | 상·하층 별도 |
| 센서 원신호 | `ControlNode` | Log에서 기록 가능 | 전기적 입력 상태 |
| 센서 물리 이벤트 순번 | `ControlNode` | Master가 중복·누락 검증 | 디바운스 이후 생성 |
| 센서 수락 및 제품 연결 | `MasterNode` | Log에서 기록 | FIFO 제품과 연결 |
| 액추에이터 동작 결정 | `MasterNode` | Control이 명령으로 수신 | 통과 또는 불량 배출 |
| 액추에이터 실제 상태 | `ControlNode` | Master가 완료 이벤트로 수신 | 완료 후 FIFO 제거 |
| 카메라 연결 상태 | `VisionNode` | Master가 상태를 수신 | 카메라별 관리 |
| 촬영 작업 상태 | `VisionNode` | Master가 성공·실패 결과를 수신 | 제품 ID·스테이션 ID 기준 |
| 추론 작업 상태 | `VisionNode` | Master가 결과를 수신 | 컨베이어와 비동기 |
| 카메라별 점수 | `VisionNode` | Master가 제품 기록에 반영 | 원점수·정규화 점수 |
| 스테이션별 비전 결과 | `VisionNode` | Master가 최종 판정에 사용 | A/B 결과 |
| 늦은 추론 결과 반영 여부 | `MasterNode` | Vision 결과를 적용하거나 무시 | `APPLIED`, `LATE_IGNORED`, `LATE_CONFLICT_IGNORED` |
| 액추에이터 분기 위치·완료 ID | `ControlNode` | Master가 `actuator_job_id`와 `completion_id`로 반영 | FIFO 제거는 맨 앞부터 순차 수행 |
| 물리 E-stop 상태 | `ControlNode` | Master가 `FAULT_STOP` 및 수동 RESET 조건으로 사용 | PoC는 TB6600 구동전원 물리 차단 |
| 카메라 하드웨어 트리거·조명 출력 | `ControlNode` | Vision은 카메라 ARMED·프레임 수집 | Control/Mega가 전기 출력 소유 |
| `FAULT_STOP` 결정 | `MasterNode` | Control이 안전 정지 수행 | Control의 즉시 안전 정지 예외 존재 |
| 영구 저장 로그 | `LogNode` | 다른 노드가 조회 요청 가능 | 운전 상태의 원본은 아님 |
| 이미지 원본 파일 생성 | `VisionNode` | Log가 상대 경로와 메타데이터 기록 | 파일 시스템 저장 |
| SQLite 검사·운전 기록 | `LogNode` | HMI와 다른 노드가 조회 요청 | 이미지 자체는 저장하지 않음 |
| 과거 로그 조회 | `LogNode` | CLI/HMI가 조회 요청 | 운전 명령 중계 없음 |
| CLI/HMI 운전 명령 | `MasterNode` | Master가 상태·guard 검증 | 개발 단계 CLI 사용 |
